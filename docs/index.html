ioc-sentinel

Extract indicators of compromise from threat reports, logs, emails and binaries, then export them as CSV, STIX 2.1, JSON or SARIF.

IOC extractor for threat intel and incident response: pulls URLs, domains, IPv4/IPv6, emails, MD5/SHA1/SHA256/SHA512, CVEs, ATT&CK IDs, crypto wallets and registry keys from text, logs and reports, refangs defanged IOCs, filters noise and exports JSON, CSV, STIX 2.1 and SARIF. Zero deps.

  1. 1 Point the @mrlouiswright scope at GitHub Packages in .npmrc

    @mrlouiswright:registry=https://npm.pkg.github.com

  2. 2 Install

    $ npm i -D @mrlouiswright/ioc-sentinel

Published to GitHub Packages, not npmjs.com. GitHub Packages needs a GitHub token with read:packages to install, even for public packages: add //npm.pkg.github.com/:_authToken=${GITHUB_TOKEN} to .npmrc or run npm login --registry=https://npm.pkg.github.com.

01 Why it exists

ioc-sentinel pulls IOCs out of any text: URLs, domains, IPv4/IPv6 addresses, email addresses, MD5/SHA1/SHA256/SHA512 hashes, CVE IDs, MITRE ATT&CK IDs, Bitcoin/Ethereum/Monero wallets, Windows registry keys and suspicious file names. It refangs defanged indicators (“hxxps://evil[.]com”, “user[@]domain(dot)ru”) before matching, removes the usual noise (private IPs, example.com, XML namespaces, setup.py-style file names) and can fail a pipeline when an IOC matches your watchlist.

CLI, library and GitHub Action. Node.js 18+, zero runtime dependencies. Binaries are never executed: printable ASCII and UTF-16LE strings are read statically.

03 Usage

# human-readable list, grouped by file

$ npx ioc-sentinel report.pdf.txt

# Example

$ npx ioc-sentinel ./case-42/ --format csv --defang > iocs.csv

# exit 1 on a watchlist hit

$ cat alert.eml | npx ioc-sentinel - -w known-bad.txt

# Example

$ npx ioc-sentinel logs/ --types url,domain,ip --stix iocs.stix.json --sarif iocs.sarif

04 CI / GitHub Action

permissions:
  contents: read
  security-events: write   # only for the SARIF upload
steps:
  - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4
    with: { persist-credentials: false }
  - uses: MrLouisWright/ioc-sentinel@v1
    with:
      targets: 'reports/'
      fail-on: critical
      sarif: ioc-sentinel.sarif
  - uses: github/codeql-action/upload-sarif@v3
    if: always()
    with: { sarif_file: ioc-sentinel.sarif }

05 Options & flags

FlagDescription
Extraction
-t, --types <list>url, domain, ipv4, ipv6, email, md5, sha1, sha256, sha512, cve, attack, btc, eth, xmr, registry, filename (also: hash, ip, wallet). Default: all
--include-privateKeep private/loopback/documentation IPs (dropped by default)
--benign <list>Domains to ignore (globs ok); replaces the built-in noise list
--no-benignDo not drop example.com, w3.org, schemas.microsoft.com etc.
--no-refangDo not refang hxxp://, [.] and friends before matching
--no-binarySkip binary files (default: extract printable strings statically)
--file-name-domainsTreat names like "setup.py"/"invoice.zip" as domains too
-w, --watchlist <file>Known-bad IOCs (one per line; CIDR and *.domain ok). Hits are critical
Export
-f, --format <fmt>text | json | sarif | markdown | csv | stix | list
--defangDefang values in csv/list output
--csv <file>Also write CSV; --stix <file> also write a STIX 2.1 bundle
Policy and output
-c, --config <file>JSON config (default .ioc-sentinel.json if present)
-f, --format <fmt>text (default) | json | sarif | markdown
--json/--sarif/--markdown <file>Also write that format to a file
--fail-on <sev>critical | high | medium | low | info | none (default critical)
--list-rulesPrint rules and default severities
--no-colorDisable colours
